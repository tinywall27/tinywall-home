# TinyWall 产品规范

> 状态：V1 当前规范。网站信息架构、页面、数据模型、搜索和设计系统已经实现；AI 采集与自动开 PR 仍是后续能力，不能描述成已经上线。

## 产品定义

TinyWall 是个人日常使用优先、公开访问友好的 Personal Information Hub / Personal OS。它把当天资讯、每日精选阅读、个人项目、常用链接和长期笔记组织在同一入口中。

TinyWall 的首要用户是站点所有者本人，公开访客是第二用户。首页必须首先解决“今天值得看什么、常用入口在哪里、最近在做什么”，而不是展示履历或营销文案。

品牌继续使用 **TinyWall**，主域名为 `tinywall.cc`。

## 产品原则

1. **打开即可使用**：进入首页后两秒内理解当天重点并进入目标内容。
2. **首页是工具，不是海报**：不使用大型营销 Hero；首屏优先呈现信息和入口。
3. **高密度但不拥挤**：主要依赖排版、层级和留白，不依赖大图卡片堆砌内容。
4. **长期可积累**：内容拥有稳定 URL、主题、日期、搜索和归档，不被一次性的时间流吞没。
5. **静态且可迁移**：内容保存在仓库中，V1 不依赖账号、数据库或专有 CMS。
6. **可信而克制**：AI 只承担采集、整理和辅助编辑，来源和最终发布责任必须清晰。

## 当前基线

当前仓库已经实现：

- Astro 静态站点与 Cloudflare Pages 发布约定；
- 以 Today 为首页的五段信息聚合；
- Reading、Projects、Links、Notes、Articles、Topics、跨内容类型 Archive 和 404；
- 独立静态 `/guides/parenting/` 育儿指南页，保留原 HTML 的分龄、主题、搜索、打印和来源，并接入全站布局、主题与搜索；
- Articles、Notes、Reading 三个内容集合，以及集中、类型化的 Projects、Links 和导航数据；
- 覆盖五类内容的命令面板（含育儿指南项目入口）与 Article/Note 正文 Pagefind 索引；
- 暖白克制的 `Editorial × Software`、顶部五项导航、系统/浅色/深色切换和响应式布局；
- 内容契约、静态构建、Pagefind、站内链接和 main/PR quality workflow。

当前尚未实现自动采集、AI 摘要、定时调度和自动创建内容 PR。

## V1 信息架构

顶部主导航固定为五项：

| 导航 | 路由 | 职责 |
| --- | --- | --- |
| Today | `/` | 当天资讯、每日精选和高频入口的聚合首页 |
| Reading | `/reading/` | 每日精选、外部阅读以及通往自写长文的统一入口 |
| Projects | `/projects/` | 个人项目状态和外部项目入口 |
| Links | `/links/` | 按主题组织的常用网址导航 |
| Notes | `/notes/` | 自己的短笔记、未成熟想法和持续记录 |

以下已有路由作为稳定的二级入口继续保留：

- `/articles/`：TinyWall 自写长文，归入 Reading 体系；
- `/articles/[slug]/`：长文详情；
- `/topics/`、`/topics/[topic]/`：按主题发现内容；
- `/archive/`、`/archive/[year]/`：按年份回看内容；
- `/404/`：未找到页面。
- `/guides/parenting/`：独立静态育儿指南页，正式归入 Projects；日常工具由 Links 提供，Today 首页 Quick Links 提供“育儿速查”入口。

育儿指南不新增内容类型，也不创建 `/guides/` 中心页。

V1 不增加第六个顶部导航项。Topics、Archive 和 Articles 应在 Reading 页面、搜索结果或页脚中可达。

## Today 首页

首页按以下固定顺序组织：

1. **日期与问候**：紧凑展示当前日期和一句轻量问候，不形成大型 Hero。
2. **Today Intelligence**：按 AI、Markets、Finance 等主题列出少量高价值资讯；显示标题、来源、时间和主题，不要求大图。
3. **Daily Read + Quick Links**：左侧突出当天最值得深入阅读的条目，右侧提供最高频网址，并保留“育儿速查”入口。
4. **Projects**：紧凑展示重要项目、状态和外部入口。
5. **Recent Notes**：列出最近更新的短笔记。

每个区块只展示足够支撑当天使用的条目，并提供通往完整列表的入口。没有当天内容时应显示诚实、简短的空状态或最近一次有效内容，不伪造“今日”数据。

## Reading 体系

Reading 是统一内容入口，但不把所有内容混成同一种类型：

- **Daily Read / External Reading**：外部文章或报告的精选条目，包含来源、摘要和推荐理由，默认直接打开原始链接；
- **Articles**：TinyWall 自己的完整长文，继续使用现有 `/articles/` URL；
- **Topics / Archive**：提供跨时间和主题的回看路径；
- **AI Daily Brief**：可以继续作为 Articles 中的受控系列，用于每天的综合编辑稿。

Reading 条目 V1 不创建本地详情页，以免复制原文；搜索结果和列表直接指向 canonical external URL。

## V1 实现状态

网站 V1 已完成：

- 已用顶部五项导航替换旧版桌面左侧栏；
- 把首页重构为 Today 聚合视图，移除大型 Hero 和大色块项目卡；
- 建立 Articles、Notes、Reading、Projects、Links 的集中、类型化数据源；
- 创建 `/reading/`、`/projects/`、`/links/`、`/notes/` 及 Notes 详情路由；
- 创建独立静态 `/guides/parenting/` 页面，并保留分龄、主题、搜索、打印和来源交互；
- 让 Topics、Archive 和全局搜索能发现适用的日期型内容；
- 提供覆盖五类内容的命令面板和搜索入口，支持 `⌘K`、`Ctrl+K`、Esc 与焦点返回；
- 保留现有内容 URL 和静态构建能力；
- 落实暖白克制的 `Editorial × Software` 视觉、三态外观切换、响应式和无障碍要求；
- 建立内容 schema、构建校验和人工 PR 审核基础。

AI 内容生成分支、定时采集和自动创建 PR 仍未实现。它们需要单独确定来源、调度器和凭据方案，并继续遵守“不得直接提交 `main`”的约束。

## V1 非目标

V1 不实现：

- 登录、用户账户、数据库、服务端 API 或 CMS；
- 跨设备同步、未读/已读、收藏、评分或外观偏好以外的浏览器持久化；
- 社交 Feed、评论、点赞、推荐算法或无限滚动；
- 完整多语言路由；
- 抓取或保存付费文章全文；
- 为每个 Reading、Project 或 Link 创建本地详情页；
- 用复杂 Bento、玻璃拟态、渐变或动画展示技术能力。

## 后续阶段

第二阶段可以加入 `/now/` 和 `/about/`，并将它们放在页脚或次级导航，不占用五个顶部主导航位置。

阅读状态、收藏和跨设备同步没有默认实施时间。只有在 V1 的静态使用体验稳定后，经过单独产品决策，才可以评估本地状态、认证和后端方案。

## V1 验收标准

- 桌面端和移动端都能从任意页面进入五个核心入口；
- 首页首屏优先显示真实信息或清晰空状态，而不是营销介绍；
- 同一项目、链接或导航项只维护一次即可在所有使用位置更新；
- 五类内容能通过全局入口被找到，JavaScript 失败时仍有基本导航路径；
- 所有已保留的内容 URL 继续有效，草稿不会进入页面、搜索或 sitemap；
- 系统/浅色/深色模式、本地偏好记忆、键盘导航、可见焦点和减少动效偏好均得到支持；
- AI 内容在合并前能追溯来源，并经过人工审核。
