# TinyWall 设计规范

> 状态：V1 当前设计规范。顶部导航、暖白 token、命令面板、系统深色模式和响应式布局已经实现，后续变更必须保持这些约束。

## 设计方向

TinyWall 的视觉语言是 **Editorial × Software**：

- Editorial 提供可信、安静、适合金融与 AI 阅读的排版；
- Software 提供清晰的状态、快速导航、键盘操作和一致反馈；
- Personal 提供温度，但不依赖头像、履历 Hero 或装饰性自我介绍。

设计应让人感觉这是一个可以长期使用的个人信息系统，而不是某一年流行的 AI 模板。

## 核心原则

1. **内容先于容器**：优先使用标题、来源、时间和标签建立层级，不为每条内容创建厚重卡片。
2. **密度来自结构**：通过紧凑行、分组、留白和细分隔线提高效率，不用缩小到难以阅读的字号。
3. **单一强调色**：陶土色只用于当前状态、链接反馈和少量关键标签；不并列使用大面积森林绿项目色块。
4. **克制的品牌表达**：TinyWall 品牌清晰存在，但页头不占据内容空间。
5. **功能性的动效**：动画只说明状态变化和空间关系，不承担装饰任务。

## 颜色 token

V1 以以下语义 token 为起点；实现时允许为 WCAG 对比度做小幅调整，但不得扩展为多强调色系统。

| Token | 浅色参考值 | 深色参考值 | 用途 |
| --- | --- | --- | --- |
| `surface` | `#fafaf8` | `#0c0d0c` | 页面背景 |
| `surface-raised` | `#fffefb` | `#141614` | 菜单、命令面板、轻量浮层 |
| `text` | `#1c211e` | `#eeeee9` | 正文与主要标题 |
| `text-muted` | `#68706a` | `#a5aaa4` | 来源、时间与辅助说明 |
| `line` | `rgba(28,33,30,.14)` | `rgba(238,238,233,.14)` | 分隔线与弱边框 |
| `accent` | `#a84f3b` | `#d97a63` | 链接、选中态与可见焦点 |

- 不使用大面积渐变作为页面背景。
- 阴影只用于必须表达层级的浮层，普通内容区块依赖边框和背景差异。
- 错误、警告和成功状态可以拥有语义色，但不得成为品牌装饰色。

## 排版

- UI、导航和元数据使用清晰的 system sans；长文标题可以使用当前 system serif。
- 正文基准字号为 16–18px，长文行高约 1.7，列表和 UI 行高约 1.4–1.55。
- 元数据不得小于 12px；英文大写标签应减少字距和使用频率，避免视觉噪声。
- 页面最大内容宽度控制在约 1100–1200px；长文正文保持约 680–760px 的可读行宽。
- 标题使用响应式 `clamp()`，首页不得出现占满首屏的巨型标题。

## 布局

### 全站框架

- 桌面端使用紧凑 sticky 顶栏，不保留固定左侧栏。
- 顶栏包含 TinyWall、五项主导航、搜索入口和当前模式提示。
- 移动端保持同样的信息层级，通过可访问菜单展示导航，不隐藏核心入口。
- 页面左右安全边距在 320px 宽度下不少于 16px，桌面端根据容器宽度增长。

### Today

- 日期和问候只占紧凑一行或一个小区块。
- Intelligence 使用按主题分组的高密度列表；每条主要显示标题、来源、时间和标签。
- Daily Read 与 Quick Links 在宽屏形成主次双栏，在窄屏按阅读优先顺序堆叠。
- Projects 使用紧凑条目或小卡片，不使用大面积彩色项目卡。
- Recent Notes 使用日期 + 标题列表，保持快速扫描。

### 内容页

- Reading、Projects、Links 和 Notes 使用一致的页面标题、筛选和列表节奏。
- 长文章继续以阅读体验为核心，目录不得挤压正文；移动端目录可折叠。
- 空状态说明发生了什么和下一条可行路径，不使用假数据填充版面。

## 组件与交互

- 默认圆角保持在 8–12px；列表行可以无圆角。
- Hover 只使用轻微背景、颜色或 1–2px 位移，不改变布局尺寸。
- 外部链接应有一致的外链标识；图标不能替代可理解的文字标签。
- 命令面板必须有明确标题、结果类型、选中态、空状态和关闭方式。
- 交互动画通常为 120–200ms，只使用 opacity 和 transform 等低成本属性。
- 禁止滚动劫持、无意义循环动画、过度视差和跟随光标的装饰效果。

## 深色模式

- V1 必须通过 `prefers-color-scheme` 自动支持系统深色模式。
- 深色模式不是简单反色；需要保持正文、弱文本、边框、代码块和焦点态的对比度。
- V1 不使用 localStorage 保存主题偏好，也不加入与“纯静态、无个人状态持久化”冲突的设置系统。
- 持久化手动主题切换只能在后续状态策略经过单独决策后加入。

## 可访问性

- 目标为 WCAG 2.2 AA。
- 所有功能可通过键盘完成，并具有清晰、持续可见的 `:focus-visible` 状态。
- 命令面板、移动菜单和其他浮层必须正确管理焦点、Esc 关闭与关闭后的焦点返回。
- 页面使用语义化标题层级、landmark、可理解链接文本和必要的 ARIA；不重复原生语义。
- 支持 `prefers-reduced-motion`，减少或取消非必要过渡。
- 不以颜色作为唯一状态提示，触控目标应适合移动设备。

## 响应式与验收

每次视觉更改至少检查：

- 320px 窄屏：无横向滚动，五个入口可达，正文不被截断；
- 768px 左右：双栏能自然转换，筛选和列表不拥挤；
- 1280px 及以上：信息密度提高但行宽受控，不出现大面积空洞；
- 浅色和深色系统模式；
- 键盘完整路径、可见焦点与减少动效模式；
- 中文长标题、英文长单词、无摘要、无当日内容等真实边界情况。
